Unlike the other five providers — which need a single API key — Azure OpenAI uses your own Azure resource, so it requires four values. In Settings → AI Provider → Your Personal API Keys, expand the ☁️ Azure OpenAI row and fill in the fields below, then click Test connection.
FieldWhat to enter
Endpointhttps://<your-resource>.openai.azure.com
API Keyportal.azure.com → your Azure OpenAI resource → Keys and Endpoint → KEY 1
Deployment nameThe name of your model deployment (e.g. gpt-4o-prod)
API VersionDefault 2024-12-01-preview
🌍
Data residency. Requests go to your own Azure resource, so your data stays in the region of that resource — ideal for enterprise data-residency requirements. Click Test connection to verify the endpoint, key, and deployment before generating.

04
Write Your Requirement
How to write requirements that generate the best test cases
1
Paste or type your requirement
Click the requirement textarea and paste your user story, BRD excerpt, or process description. You can type up to 6,000 characters — the counter shows your current count.
shuddhiqacloud.vercel.app/app
Describe Your Requirement (Required)
Vendor submits invoice via portal. AP Clerk performs 3-way match (Invoice, PO, Goods Receipt). If amount ≤ ₹50,000, auto-approved. If > ₹50,000, Finance Manager must approve within 2 business days. On approval, payment is scheduled to vendor bank account. On rejection, vendor receives email with reason.
312 / 6,000
2
Writing a good requirement
The quality of your test cases directly depends on the clarity of your requirement. Include roles, thresholds, and expected outcomes.
✅ Good Requirement❌ Poor Requirement
Includes user roles (AP Clerk, Finance Manager)Generic — "test the invoice process"
Includes thresholds (≤ ₹50,000 / > ₹50,000)No boundary values
Includes expected outcomes (payment scheduled, email sent)No expected results
Includes error scenarios (rejection flow)Only happy path described
200–500 charactersSingle sentence

06
Review & Edit Test Cases
Inline editing and select-all controls
1
Enter Edit Mode
Click the ✏️ Edit button in the export toolbar to enter inline edit mode. Every cell in the test case table becomes clickable.
💡Edit mode is non-destructive — you can exit without saving by clicking Edit again to toggle off.
2
Edit any cell
Click any cell — test case title, step action, expected result — to edit inline. Changes reflect immediately in all export formats.
3
Select / Deselect All Test Cases
Use the checkbox at the top of the table to select all or deselect all test cases at once. This controls which TCs get exported.
shuddhiqacloud.vercel.app/app

💡
Toggle behavior (v12.15+): None selected → click → all selected. All selected → click → none selected. Some selected → shows indeterminate dash → click → all selected.
07
Export to Excel / PDF
Download test cases for stakeholder review
1
Export to Excel
Click 📊 Excel in the export toolbar. A .xlsx file downloads automatically with separate sheets per test case type (E2E, Smoke, Validation, etc.).
💡Only selected test cases (checked checkboxes) are included in the export.
2
Export to PDF
Click 📑 PDF in the export toolbar. A formatted PDF downloads with all test cases, steps, and expected results — ideal for sign-off packages or sharing with non-technical stakeholders.
3
Copy Markdown
Click 📋 Markdown to copy all test cases to clipboard in Markdown format. Paste directly into Confluence, Notion, or any Markdown editor.

Push to Azure DevOps
Create test plans and push test cases directly to ADO
1
Create an ADO Personal Access Token (PAT)
In Azure DevOps, create a PAT with the correct scope.
Steps to create ADO PAT
Go to dev.azure.com → your org
Click your profile icon (top right) → Personal Access Tokens
Click + New Token
Name: ShuddhiQA-PAT (or any name)
Expiration: 90 days recommended
Scopes: tick Test Plans (Read & Write) + Work Items (Read & Write)
Click Create → Copy the token immediately (shown once only)
2
Configure ADO in Settings
Click ⚙️ Settings → Azure DevOps tab → enter your Org URL and PAT → click Test Connection.

Export to Jira Zephyr
Generate CSV for Jira Zephyr Squad or Scale import
1
Get your Atlassian API Token
Steps to get Atlassian API token
Go to id.atlassian.com
Click Security → API tokens → Create API token
Name: ShuddhiQA (or any label)
Click Create → Copy the token
2
Configure Jira in Settings
Click ⚙️ Settings → Jira tab → enter your API token, email, and Jira domain (e.g. yourcompany.atlassian.net without https://).
3
Export Jira Zephyr CSV
After generating test cases, click More ▾ in the export toolbar → click 🟦 Jira Zephyr. A CSV file downloads with all 10 Zephyr headers pre-populated.
📥In Jira: Go to Zephyr Squad → Test Cases → Import → Upload the CSV file.

Iterative Refinement
Regenerate individual test cases with additional context
1
Hover over a test case
Move your mouse over any test case row. A 🔄 regenerate button appears on the right side of the row.
2
Click the regenerate button
The Regeneration modal opens showing the original test case title and an optional context field.
🔄 Regenerate TC001✕
Original: E2E: Successful 3-Way Match & Auto-Approval (≤₹50,000)
Additional Context (Optional)
Cancel🔄 Regenerate
3
Add context and regenerate
Add specific instructions in the context field (optional) then click Regenerate. Only that one test case is updated — the rest of the suite stays unchanged.
💡
Good context examples: "Focus on boundary conditions", "Add steps for currency conversion", "Include UAT login credentials format", "Add more negative scenarios"

Sign In with Google or Microsoft
Click Sign In in the top navigation → Click "Continue with Google" or "Continue with Microsoft (work account)" → Complete the OAuth flow in the popup.
🔒
Privacy: Only your name and email are accessed for identification. No access to Gmail, Drive, Calendar, or any other Google service. Sign-in uses standard OAuth 2.0 with email + profile scopes only.
3
Delete Your Data
Click your name/avatar in the header → Delete my data & account. This permanently deletes your Firestore document and Firebase Auth account. Your browser-stored API keys can be cleared separately via Settings → Clear All.
